# Introduction to Conda
**_Package and Environment Management_**

---

## 1. Why isolated software environment?

- **Versioning**: your project needs specific versions of software packages.
- **Reproducibility**: you have a working pipeline and want to try new packages (or new features of existing ones) without breaking it.
- **Repeatability**: you want to replicate published results, or let others replicate yours.
- **Compatibility**: a collaborator's workflow needs a tool that clashes with your system (e.g. Python 2.7 vs Python 3).

One machine can run several analyses, each in its own isolated environment with its own packages. For example, one person runs three analyses:

| Analysis | Environment name | Example packages |
|---|---|---|
| QC | `qc` | FastQC |
| Assembly | `assembly` | BWA |
| Phylogenetics | `phylogenetics` | IQ-TREE |

The same tool can live in several environments, each at a different version.

## 2. Terminology

### 2.1 Which tool do we use? Mamba

**In this course, use `mamba` for every command. Do not use `conda`.**

| Tool | Use it? | Why |
|---|---|---|
| **mamba** | **Yes, always** | Faster solver, same packages and channels, same environments |
| **conda** | No | Slower. Old guides and online answers use it; translate those commands with the table in section 6 |

Why we stick with mamba:

- It is faster at resolving and installing packages.
- It reads the same channels and config file as conda, and it creates the same kind of environments. Nothing is lost by using it.
- Mixing the two tools in one environment can break it, so do not switch between them.

If a `mamba` command does not work, check the table in section 6 first. Then check the version with `mamba --version`, and ask your instructor if it still fails.

### 2.2 Terms

| Term | What it is |
|---|---|
| **Anaconda** | Large free distribution of Python and R for scientific computing (many packages pre-installed) |
| **Miniconda** | Minimal installer for conda |
| **Miniforge** | Community-driven minimal conda installer; uses the `conda-forge` channel by default. This is the one we install. |
| **Conda** | Package manager and environment manager (developed by Anaconda, Inc.). Used by the installer, but not by us. |
| **Mamba** | Community-developed, faster drop-in replacement for conda. This is the one we use. |
| **Channel** | A repository packages are downloaded from (`conda-forge`, `bioconda`) |

## 3. Installing Miniforge

Download page: <https://github.com/conda-forge/miniforge>
(Other options: Anaconda <https://www.anaconda.com/download>, Miniconda <https://docs.conda.io/projects/miniconda/en/latest/index.html>)

### 3.1 Install

```bash
# Download the installer for your OS and CPU architecture
curl -L -O "https://github.com/conda-forge/miniforge/releases/latest/download/Miniforge3-$(uname)-$(uname -m).sh"

# Run it (accept the licence, accept the default location, say "yes" to initialise conda)
bash Miniforge3-$(uname)-$(uname -m).sh
```

Close and reopen the terminal. You should now see `(base)` at the start of your prompt. This is the default environment that comes with Miniforge.

### 3.2 Configure channels (one-time, for bioinformatics tools)

Bioinformatics tools such as FastQC, BWA and IQ-TREE are on the **bioconda** channel. Therefore, we need to add it to our channels so that mamba can find them.

Mamba uses the first channel in the list with the highest priority, so add them in this order:

```bash
mamba config prepend channels bioconda
mamba config prepend channels conda-forge
mamba config set channel_priority strict

# check
mamba config list channels
```

The check should print `conda-forge` first and `bioconda` second.

> If you prefer not to change your config, add `-c bioconda -c conda-forge` to each `mamba install` or `mamba create` command instead.

## 4. The base environment

`(base)` is created at install time. **Avoid installing analysis tools into base.** Keep it clean and create a separate environment per project or analysis.

## 5. Worked example: three analyses, three environments

**Scenario:** one person runs three analyses: **QC**, **assembly** and **phylogenetics**. Each gets its own environment so the tools and their dependencies cannot interfere with each other.

### 5.1 Create the three (empty) environments

```bash
mamba create -n qc
mamba create -n assembly
mamba create -n phylogenetics
```

Check they exist:

```bash
mamba env list
```

```
# conda environments:
#
base                 *  /home/user/miniforge3
assembly                /home/user/miniforge3/envs/assembly
phylogenetics           /home/user/miniforge3/envs/phylogenetics
qc                      /home/user/miniforge3/envs/qc
```

Note that the environments were created **without** any packages. We install tools into them afterwards.

### 5.2 Install a tool into each environment

**QC → FastQC**

Run only one of the four install lines below. They are alternatives, not a sequence.

```bash
mamba activate qc

# Step 1: default channel, newest version available.
# Simplest option, but the version may change over time.
mamba install fastqc

# Step 2: default channel, pinned version.
# =0.12.1 installs exactly version 0.12.1.
mamba install fastqc=0.12.1

# Step 3: named channel, newest version.
# bioconda:: makes sure FastQC comes from bioconda, where bioinformatics tools are kept.
mamba install bioconda::fastqc

# Step 4: named channel and pinned version.
# Most reproducible option: the channel and the version are both stated.
mamba install bioconda::fastqc=0.12.1

fastqc --version
mamba list fastqc

mamba deactivate
```

**Assembly → BWA**

```bash
mamba activate assembly

# Install BWA from the default channels, newest version available.
mamba install bwa

bwa            # prints usage and the version
mamba list bwa

mamba deactivate
```

**Phylogenetics → IQ-TREE**

```bash
mamba activate phylogenetics

# Install IQ-TREE from the default channels, newest version available.
mamba install iqtree

iqtree3 --version     # or iqtree2 --version, depending on the installed major version
mamba list iqtree

mamba deactivate
```

### 5.3 Delete the QC environment

Say the QC work is finished and we no longer need that environment.

```bash
mamba deactivate                 # make sure you are not inside qc
mamba env remove -n qc
mamba env list                   # qc is gone; assembly and phylogenetics remain
```

```
# conda environments:
#
base                 *  /home/user/miniforge3
assembly                /home/user/miniforge3/envs/assembly
phylogenetics           /home/user/miniforge3/envs/phylogenetics
```

Deleting an environment removes only that environment. The other two are untouched, which is the whole point of isolation.

## 6. Most commonly used commands

All commands use `mamba`. Use this table to translate any old `conda` command you find elsewhere.

| Task                    | Command                                                                            |
| ----------------------- | ---------------------------------------------------------------------------------- |
| Create an environment   | `mamba create -n <env>`                                                            |
| List all environments   | `mamba env list`                                                                   |
| Activate an environment | `mamba activate <env>`  # here <env> is the name of the environment, e.g. assembly |
| Deactivate              | `mamba deactivate`                                                                 |
| Install a package       | `mamba install <package>`                                                          |
| Install from a channel with a version | `mamba install <channel>::<package>=<version>`                       |
| List installed packages | `mamba list`                                                                       |
| Update a package        | `mamba update <package>`                                                           |
| Remove a package        | `mamba remove <package>`                                                           |
| Remove an environment   | `mamba env remove -n <env>`                                                        |
| Search for a package    | `mamba search <package>`                                                           |
| Show configuration      | `mamba config list`                                                                |

---

## 7. Good habits

- Use `mamba` for every command, never `conda` (see section 2.1).
- One environment per project or analysis. Give them meaningful names.
- Don't install analysis tools into `base`.
- Activate the environment **before** running `mamba install`.
- Install related tools together in one command so mamba can resolve compatible versions in one go.
- Use `mamba list` to record exactly what is installed (and which versions) when writing up methods.
