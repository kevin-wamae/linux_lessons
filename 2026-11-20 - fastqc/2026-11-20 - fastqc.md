## 4. Look at the data first

We did not do this in class. Each read in a FASTQ file takes **4 lines**:

```
@M03021:9:000000000-LD8J7:1:1101:19718:1924 1:N:0:31   <- 1. read ID
CCCATAATCCGAATTTTGCATTC...                             <- 2. sequence
+                                                      <- 3. separator
CCCCCE<...                                             <- 4. quality, one character per base
```

Sequence files are huge, so they are stored compressed (`.gz`). You can read them without unzipping, using `zcat` (Linux) or `gzcat` (macOS), and pipe the output into the commands you already know:

```bash
ls
zcat sample1_R1.fastq.gz | head -8
zcat sample1_R1.fastq.gz | wc -l        # number of lines; divide by 4 to get the number of reads
```

### Quick exercises

1. How many reads are in `sample1_R1`? In `sample1_R2`? Should they match? Why?
2. Print the first 5 read IDs (`awk` is a new command; here it selects every 4th line starting at line 1):

   ```bash
   zcat sample1_R1.fastq.gz | awk 'NR%4==1' | head -5
   ```
3. How long are the reads? (the sequence is every 4th line starting at line 2)

   ```bash
   zcat sample1_R1.fastq.gz | awk 'NR%4==2 {print length($0)}' | sort -n | uniq -c
   ```

### Quality scores

Each character on the quality line encodes a Phred score `Q`. The probability that the base is wrong is `10^(-Q/10)`.

| Q   | Chance base is wrong | Meaning    |
| --- | -------------------- | ---------- |
| 10  | 1 in 10              | poor       |
| 20  | 1 in 100             | acceptable |
| 30  | 1 in 1,000           | good       |
| 40  | 1 in 10,000          | excellent  |

## 5. The script: `qc_report.sh`

We provide a script that runs FastQC for you. It creates a `qc_report` directory and runs FastQC on the two `sample1` files (R1 and R2), writing the results into `qc_report`.

```bash
#!/bin/bash

# create a directory to store the qc reports
mkdir -p qc_report

# run fastqc on the fastq files
fastqc sample1_R1.fastq.gz sample1_R2.fastq.gz \
            --threads 2 \
            --format fastq \
            --outdir qc_report
```

Line by line:

| Line                                        | Idea                                                                    |
| ------------------------------------------- | ----------------------------------------------------------------------- |
| `#!/bin/bash`                               | Shebang: which interpreter runs the script                              |
| `# ...`                                     | Comment, ignored by bash                                                |
| `mkdir -p qc_report`                        | Create the output directory; `-p` means no error if it already exists   |
| `fastqc ... \`                              | A backslash at the end of a line continues the command on the next line |
| `--threads 2`, `--format fastq`, `--outdir` | Options (flags) with values                                             |

Useful FastQC options (`fastqc --help` lists all):

| Option          | What it does                                                            |
| --------------- | ----------------------------------------------------------------------- |
| `-o, --outdir`  | Where results go. The directory must already exist.                     |
| `-t, --threads` | Number of files processed in parallel                                   |
| `-f, --format`  | Input format (`fastq`, `bam`, `sam`); detected automatically if omitted |
| `-q, --quiet`   | Print less                                                              |

## 6. Run FastQC and read the report

### 6.1 Run the script

Activate the environment, then run the script with `bash`:

```bash
mamba activate fastqc
bash qc_report.sh
ls qc_report
```

For each input file you get:

| File            | Use                                        |
| --------------- | ------------------------------------------ |
| `*_fastqc.html` | Report to open in a browser                |
| `*_fastqc.zip`  | The same data as text, used by other tools |

### 6.2 Read a FastQC report

Open `qc_report/sample1_R1_fastqc.html` in a browser and compare it with R2.

| Module                           | What to look for                                                                      |
| -------------------------------- | ------------------------------------------------------------------------------------- |
| **Basic Statistics**             | Total sequences, read length, %GC. Does it match your `wc -l` count?                  |
| **Per base sequence quality**    | Quality along the read. Usually falls toward the 3' end; R2 is usually worse than R1. |
| **Per sequence quality scores**  | Most reads should peak at a high Q (above 30).                                        |
| **Per base sequence content**    | Lines roughly flat. Wobble in the first bases is common.                              |
| **Per sequence GC content**      | One bump near the theoretical curve. Several bumps suggest contamination.             |
| **Per base N content**           | Near 0.                                                                               |
| **Sequence length distribution** | One peak for untrimmed data.                                                          |
| **Sequence duplication levels**  | High duplication: low-complexity library or over-amplification.                       |
| **Overrepresented sequences**    | Often adapters or contaminants.                                                       |
| **Adapter content**              | Adapter at the 3' end means trimming is needed.                                       |

PASS / WARN / FAIL are rules of thumb, not verdicts. A FAIL on GC content, for example, can be normal for an AT-rich genome.
