## 4. Why trim?

Sequencing reads often have two problems:

- **Adapters**: short artificial sequences added during library preparation. If the DNA fragment is shorter than the read, the read runs into the adapter.
- **Low quality bases**: quality usually drops toward the 3' end of the read.

Both hurt downstream analysis (assembly, mapping), so we remove them first.

## 6. Adapter trimming with flexbar

```bash
mkdir -p output/flexbar
flexbar -z GZ -a data/adapters.fasta \
        --reads data/SRR957824_50K_R1.fastq.gz \
        --reads2 data/SRR957824_50K_R2.fastq.gz \
        --target output/flexbar/SRR957824_50K
ls output/flexbar
```

| Option | What it does |
|---|---|
| `-z GZ` | Compress the output with gzip |
| `-a data/adapters.fasta` | File with the adapters to remove |
| `--reads`, `--reads2` | The R1 and R2 files |
| `--target` | Prefix for the output files (here: inside `output/flexbar`) |

The output files are `SRR957824_50K_1.fastq.gz` and `SRR957824_50K_2.fastq.gz`.

## 7. Quality trimming with trimmomatic

`trimmomatic` cuts each read down to its good quality part. We use two filters:

- `SLIDINGWINDOW:4:20`: move a window of 4 bases along the read and cut where the average quality in the window drops below 20.
- `MINLEN:20`: drop reads shorter than 20 bases after trimming.

```bash
mkdir -p output/trimmomatic
trimmomatic PE \
    output/flexbar/SRR957824_50K_1.fastq.gz output/flexbar/SRR957824_50K_2.fastq.gz \
    output/trimmomatic/SRR957824_50K_R1_paired.fastq.gz output/trimmomatic/SRR957824_50K_R1_unpaired.fastq.gz \
    output/trimmomatic/SRR957824_50K_R2_paired.fastq.gz output/trimmomatic/SRR957824_50K_R2_unpaired.fastq.gz \
    SLIDINGWINDOW:4:20 MINLEN:20
```

`PE` means paired-end: two inputs and four outputs (a *paired* and an *unpaired* file for each of R1 and R2).

The summary should look like this:

```
Input Read Pairs: 43132 Both Surviving: 41616 (96.49%) Forward Only Surviving: 1025 (2.38%) Reverse Only Surviving: 265 (0.61%) Dropped: 226 (0.52%)
```

```bash
ls -lh output/trimmomatic
```

## 9. The script: `trim.sh`

Instead of typing every command, we use a script, like last week's `qc_report.sh`. This one is not tied to one file: it finds **every** `*_R1.fastq.gz` file in `data/`, works out the matching R2 file, and runs the whole workflow on each pair.

Create `trim.sh` in `2026_11_27_trimming/` with `nano`:

```bash
#!/bin/bash

# stop the script if any command fails
set -e

# go to the project directory, so the script works from anywhere.
# All the paths below (data/, output/) are relative to this directory.
cd ~/linux_lessons/2026_11_27_trimming

# Create a directory for the output of each step.
# -p means: no error if the directory already exists.
mkdir -p output/fastqc_before_trimming
mkdir -p output/flexbar
mkdir -p output/trimmomatic
mkdir -p output/fastqc_after_trimming
mkdir -p output/multiqc

# Step 1: run FastQC on the raw reads.
# data/*.fastq.gz is a wildcard: it matches every .fastq.gz file in data/.
echo "=== Step 1: running FastQC on the raw reads ==="
fastqc data/*.fastq.gz \
       --threads 2 \
       --outdir output/fastqc_before_trimming

# Steps 2 and 3: adapter and quality trimming.
# flexbar and trimmomatic handle one pair of files at a time, so we loop
# over every R1 file and find its R2 partner:
#   r1:     the current R1 file, e.g. data/SRR957824_50K_R1.fastq.gz
#   r2:     the same name with _R1 replaced by _R2 (${variable/old/new})
#   sample: the file name without the folder and without _R1.fastq.gz,
#           e.g. SRR957824_50K
for r1 in data/*_R1.fastq.gz; do

    r2=${r1/_R1/_R2}
    sample=$(basename "$r1" _R1.fastq.gz)

    echo "=== Processing sample: $sample ==="

    # Step 2: remove adapters.
    # --target is the prefix of the output files; flexbar adds _1 and _2.
    echo "Step 2: removing adapters with flexbar"
    flexbar -z GZ \
            -a data/adapters.fasta \
            --reads "$r1" \
            --reads2 "$r2" \
            --target "output/flexbar/$sample"

    # Step 3: trim low quality bases.
    # PE = paired-end: 2 input files, then 4 output files
    #   (a paired and an unpaired file for each of R1 and R2).
    # SLIDINGWINDOW:4:20 cuts where the average quality in a 4-base window is below 20.
    # MINLEN:20 drops reads shorter than 20 bases.
    echo "Step 3: trimming low quality bases with trimmomatic"
    trimmomatic PE \
        "output/flexbar/${sample}_1.fastq.gz" \
        "output/flexbar/${sample}_2.fastq.gz" \
        "output/trimmomatic/${sample}_R1_paired.fastq.gz" \
        "output/trimmomatic/${sample}_R1_unpaired.fastq.gz" \
        "output/trimmomatic/${sample}_R2_paired.fastq.gz" \
        "output/trimmomatic/${sample}_R2_unpaired.fastq.gz" \
        SLIDINGWINDOW:4:20 \
        MINLEN:20
done

# Step 4: run FastQC on the trimmed reads.
# Only the paired files: the unpaired ones are leftovers.
echo "=== Step 4: running FastQC on the trimmed reads ==="
fastqc output/trimmomatic/*_paired.fastq.gz \
       --threads 2 \
       --outdir output/fastqc_after_trimming

# Step 5: combine all the reports into one page.
echo "=== Step 5: combining all reports with MultiQC ==="
multiqc output/fastqc_before_trimming \
        output/fastqc_after_trimming \
        --outdir output/multiqc

echo "=== DONE: open output/multiqc/multiqc_report.html ==="
```

Line by line:

| Line | Idea |
|---|---|
| `set -e` | Stop the script at the first error |
| `cd ~/linux_lessons/2026_11_27_trimming` | Go to the project directory first, so the relative paths (`data/`, `output/`) work wherever you start the script |
| `mkdir -p output/...` | Create the output directory for each step |
| `echo "..."` | Print a message, so we know where the script is |
| `data/*.fastq.gz` | Wildcard: matches every file in `data/` ending in `.fastq.gz` |
| `for r1 in data/*_R1.fastq.gz; do ... done` | Loop: runs the commands once for each R1 file; `r1` holds the current file name |
| `${r1/_R1/_R2}` | Replace `_R1` with `_R2` in the file name, to get the R2 file |
| `$(basename "$r1" _R1.fastq.gz)` | Remove the folder and the `_R1.fastq.gz` ending, leaving the sample name |
| `"$r1"` | Use the value of a variable; always put it in quotes |
| `--target` | flexbar option: the prefix of the output files, so each sample gets its own |
| `\` | Continue the command on the next line |

New files in `data/` are picked up automatically.

Run it with the environment active:

```bash
mamba activate trimming
cd ~/linux_lessons/2026_11_27_trimming
bash trim.sh
ls output/*
```

Open `output/multiqc/multiqc_report.html`.
